## 2. Сценариогоос SLO ба Threshold болгосон Хүснэгт

| Сценарио | SLI (Юуг хэмжих) | SLO Босго | k6 Threshold Код | Сонгосон Үндэслэл |
| :--- | :--- | :--- | :--- | :--- |
| **Performance** | `/cart/add` latency | p95 < 200 мс | `http_req_duration{name:cart}: p(95)<200` | Localhost дээр хурдан тул 200мс хангалттай босго |
| **Reliability** | `/pay` error rate | < 8% | `http_req_failed{name:pay}: rate<0.08` | Кодод ~5% алдаа суулгасан тул 8% бодит босго |
| **Availability** | Амжилттай хүсэлт % | > 90% | `checks: rate>0.90` | 2 мин цонхонд ~10с зогсолтын нөлөөг хэмжих босго |

## 3. Error Budget Тооцоо ба Ажиглалт

- **Цагаар тооцсон Error Budget:** 2 минутын (120с) цонхонд 90% Availability гэдэг нь **12 секундийн эвдрэх эрх** (Error budget) өгнө.
- **Хүсэлтээр тооцсон Availability-ийн зөрүү:** Сервер унах үед хүсэлтүүд агшин зуур алдаа заан буцдаг тул зогсолтын үед олон хүсэлт бүтэлгүйтэж, бодит туршилтаар `checks` болон `http_req_failed{name:pay}` (`30.30%`) threshold-ууд давсан (`crossed`) үр дүн гарсан. Иймд ЦАГААР тооцсон budget болон ХҮСЭЛТЭЭР тооцсон checks-ийн % зөрдөг.

## 4. Дүгнэлт ба Ажиглалт (8-10 өгүүлбэр)

1. Энэхүү лабораториор "Чанарын сценарио → SLO → k6 threshold" шилжилтийн бүтэн шугамыг Node.js Express локал API болон Grafana k6 хэрэгслээр биечлэн тууллаа.
2. 6 хэсэгтэй форматаар бичсэн сценарионуудыг SLI хэмжүүр болгон томьёолж, `slo-test.js` кодод tag ашиглан threshold болгон кодчилов.
3. `results/pass.txt` тохиолдолд тохируулсан бүх SLO-нууд амжилттай биелж PASS гарсан.
4. Mini Chaos туршилтын үед серверийг ~10 секунд унтрааж дахин асаахад `checks` болон `http_req_failed{name:pay}` (`30.30%`) threshold-ууд давж, системийн доголдол бодит хэмжүүрээр хэрхэн илрэхийг ажиглав.
5. Сервер унах үед хүсэлтүүд шууд алдаа буцаадаг тул цагаар тооцсон 12 секундийн budget болон k6-ийн хүсэлтээр тооцсон checks % зөрж байгааг онолын хувьд тайлбарлав.
6. `slo-test-fail.js` туршилтаар `/report`-ийн p95 босгыг 100мс болгон хатууруулахад `p(95)=393.71ms` болж тест FAIL болсон.
7. Уг FAIL туршилтын үед k6 нь `Exit code: 99` буцааж байгааг `results/fail.txt` файлд баталгаажуулан хадгалсан.
8. Энэхүү exit code нь CI/CD pipeline дээр чанаргүй кодын түгээлтийг автомат зогсоох Quality Gate болон ажилладгийг ойлгож авсан.
9. Ингэснээр системийн чанарын шаардлагыг хэмжигдэхүйц тоон үзүүлэлт болгож, автомат шалгалтаар баталгаажуулах практик ур чадвар эзэмшлээ.
